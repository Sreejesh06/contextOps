# README GIF Creator

A repository-aware GIF creation skill.

Your job is **not simply to generate an animation.**

Your job is to understand the project like an experienced open source maintainer and create a memorable visual identity for it.

The GIF should instantly communicate

- what the project does
- its personality
- its workflow
- why someone would care

The animation becomes the hero section of the README.

---

# Primary Goal

After analyzing the repository:

1. Understand the project.
2. Identify its core purpose.
3. Extract the most visually interesting concepts.
4. Design a unique animation.
5. Generate an optimized GIF.
6. Insert it at the very top of README.md.

Example:

```markdown
<p align="center">
<img src="docs/assets/project.gif" width="700">
</p>

# Project Name
```

---

# Repository Analysis

Before drawing anything, inspect the entire repository.

Analyze:

- README
- source code
- architecture
- package.json
- pyproject.toml
- Cargo.toml
- go.mod
- docs
- examples
- tests
- CLI commands
- APIs
- UI
- workflows
- branding
- logos
- icons

Determine:

- What problem does this solve?
- What is unique?
- What should users remember?
- What visual metaphor best represents it?

Never guess.

---

# Animation Philosophy

The animation should feel like it was crafted by a designer—not generated by AI.

Avoid:

- floating random shapes
- generic particles
- stock loading animations
- spinning cubes
- rainbow gradients everywhere
- fake futuristic HUDs
- random glowing circles
- overused AI aesthetics

Instead create something that belongs specifically to THIS repository.

Examples:

A Git visualization tool

→ animated branching graph

A compiler

→ code transforming into machine instructions

A CLI

→ realistic terminal workflow

A scheduler

→ flowing timeline

A database

→ animated data movement

An AI framework

→ information transforming through pipelines

A networking library

→ packets flowing between nodes

A graphics engine

→ wireframes becoming rendered scenes

Every repository deserves a unique concept.

---

# Visual Quality

Animations should look professionally designed.

Requirements:

- smooth motion
- proper easing
- balanced composition
- intentional colors
- depth
- shadows
- highlights
- subtle motion
- consistent spacing

Avoid flat primitive drawings.

Objects should have weight.

Motion should feel natural.

---

# Creativity Rules

Never reuse templates.

Never reuse layouts.

Never reuse timing.

Every project deserves a custom animation.

If two repositories are different,

their GIFs should look completely different.

---

# Storytelling

The GIF should tell a story.

Example structure:

Frame 1

Introduce the project

↓

Frame 2

Show the input

↓

Frame 3

Show transformation

↓

Frame 4

Reveal the output

↓

Frame 5

Loop seamlessly

Think like motion graphics rather than icons.

---

# Technical Constraints

README Hero GIF

Recommended:

- 900–1400 px wide
- 16:9 or 21:9
- 12–24 FPS
- 2–6 seconds
- seamless loop
- optimized file size

Output:

```
docs/assets/project.gif
```

---

# Optimization

Optimize without sacrificing quality.

Use:

- palette optimization
- duplicate frame removal
- perceptual color reduction
- delta encoding
- proper frame timing

Target:

<5MB whenever possible.

---

# README Integration

Automatically update README.

Insert only if not already present.

Example:

```markdown
<p align="center">
  <img src="docs/assets/project.gif" alt="Project animation">
</p>

# Project Name
```

Maintain existing badges.

Maintain formatting.

Never duplicate GIF sections.

---

# Style Guide

Aim for the quality of:

- Stripe engineering
- Vercel
- Linear
- Raycast
- Framer
- Clerk
- Supabase
- Astro

Minimal.

Elegant.

Confident.

Purposeful.

---

# Hard Rules

Never create:

- AI-looking art
- clipart
- emoji animations
- meme GIFs
- random neon effects
- unnecessary particles
- meaningless motion

Every animation element must communicate something about the repository.

---

# Validation Checklist

Before saving:

✓ The repository has been fully analyzed.

✓ The animation reflects the repository.

✓ Motion is smooth.

✓ Loop is seamless.

✓ The GIF feels handcrafted.

✓ The README was updated.

✓ File size is optimized.

✓ No generic AI aesthetic exists.

If any check fails,

redesign the animation.

---

# Goal

When someone opens the repository, the GIF should make them immediately understand what the project is and think:

> "This animation was clearly designed specifically for this project."

It should feel like an intentional part of the project's identity—not an automatically generated asset.
